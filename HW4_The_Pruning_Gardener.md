# Homework 4: The Pruning Gardener
## CS 311: Data Structures & Algorithms (Fall 2026)

### 🌳 The Mission
Lab 8's search engine index can find records and print its own shape, but it can never forget anything — there's no way to remove a record once it's indexed. When a student withdraws from USI, their record has to come out of the index cleanly, without breaking the BST property for the thousands of records left behind. Deletion is the one BST operation that actually has three different cases to get right depending on how many children the node has. Your task is to implement it correctly, plus one more query the registrar actually asked for: "give me the k-th ranked record without scanning the whole tree."

### Part A: The Three Cases (50 Points)
**Instructions:** Answer the following questions in a separate document (PDF or Markdown). Describe and trace the deletion cases in Questions 1–3. For Question 4, write a formal inductive proof with an explicit base case and inductive step.

1. **Case Enumeration:**
   BST deletion of a node `N` has exactly three cases, based on how many children `N` has. For each case, describe in one or two sentences what must happen to keep the BST property intact:
   (a) `N` is a leaf. (b) `N` has exactly one child. (c) `N` has two children.
2. **The Inorder Successor Trick:**
   For the two-children case, the standard technique replaces `N`'s value with its **inorder successor** (the smallest value in `N`'s right subtree), then deletes that successor node instead. Explain why the inorder successor is *guaranteed* to have at most one child, which is what makes this trick reduce case (c) down to case (a) or (b) instead of needing a fourth case.
3. **Visual Tracing:**
   Starting from the BST built by inserting `50, 25, 75, 10, 30, 60, 80, 5` (the Lab 8 tree), delete `25` (a two-children case).
   - Show the tree immediately before deletion, identify the inorder successor used, and draw the tree immediately after.
4. **Proof by Induction — Deletion Preserves the BST Property:**
   Prove by induction on tree height that, for any of the three cases in Question 1, a correctly implemented `delete` preserves the BST property (every node's left subtree is entirely less, right subtree entirely greater) for the resulting tree. State your base case explicitly (a tree of height 0 — a single node, necessarily a leaf deletion).

   > [!CAUTION]
   > **The Brutality Clause:** A proof missing an explicitly stated base case receives an automatic **0** on this question, regardless of the correctness of the inductive step.

### Part B: The Pruner (50 Points)
**Instructions:** Complete `delete`, `count_nodes`, and `kth_smallest` in the provided `prune_tree.py`. `TreeNode` and `insert` are given — reuse the same shape as Lab 8.

**Requirements:**
1. `delete(root, key)` must be implemented **recursively**, correctly handling all three cases from Part A, and must return the new subtree root (since deleting the root itself requires the caller to reassign their reference).
2. `count_nodes(root)` must be recursive and return the total number of nodes in the subtree rooted at `root` (0 for `None`).
3. `kth_smallest(root, k)` must find the `k`-th smallest key (1-indexed) **without** performing a full inorder traversal into a list first — use `count_nodes` on subtrees to decide whether to recurse left, return the current node, or recurse right with an adjusted `k`, so a call only visits nodes along a single root-to-target path plus the subtree-size checks at each step, not the whole tree.
4. **Base Case Required:** `delete`, `count_nodes`, and any recursive helper `kth_smallest` uses must correctly handle an empty subtree (`None`). Remember the **Brutality Clause**.
5. **Verification:** Run the script using `python test_prune.py`. It replays the Part A, Question 3 deletion, then stress-tests random sequences of inserts and deletes (checking the BST property holds after every single deletion) and checks `kth_smallest` against a plain-sort reference for many random `k`. If everything matches, the script prints the **Success Token**.
